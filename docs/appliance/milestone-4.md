# Milestone 4 implementation plan

A fresh Pi 5 should reach Home with a TV remote, play indexed media offline, and find and play a movie and an episode online with only household network access and a personal TorBox account. A viewer can add media folders, Prowlarr or an iOS remote later from Settings. The exit test starts with empty appliance userdata on a different household network, with Prowlarr unconfigured and the owner’s home server offline.

Start on the `appliance` branch at `bbc6136a7f25e96d44dd65e8d67bc01282e247e5`. That checkpoint contains the M3 desktop acceptance driver. The tested M3 product and image use `15bfac9b152c55d5e0ec5af431ded9a0737fc873`. Keep the existing profile-scoped title anchors, selector, player callbacks and Kodi bookmarks throughout. Build product behavior in native C++, use Estuary XML for presentation, and extend the existing synthetic fixtures. [Requirements](requirements.md) · [Playback contract](stream-selection.md) · [M3 desktop evidence](handoff.md#point-5-desktop-acceptance) · [Open hardware records](handoff.md#point-5-pi-5-records)

## 1. Get one local title from a clean profile to the screen

1. Extend the desktop fixture with an empty profile, one generated video and a local movie NFO with a synthetic TMDB ID. Drive a user through **Use local media → Home → Settings → Media folders → Add folder → Search → detail → Play** using navigation keys. The fixture supplies the *input folder*. The app must produce the library record, anchor and local association itself. The existing `library_check` seeds these by hand and remains a compatibility test. [Desktop driver](test_appliance_playback.py)
2. In Estuary, make Home expose Search, Favorites, Continue Watching and Settings. Start with working empty states and a Play/Resume detail action. Reuse Kodi's focused lists, keyboard, video detail window and playback OSD. Keep visible focus on return from detail, stable focus when results arrive, readable localized labels, and working Back from empty/error screens. Keep stock media categories, add-on installation and skin switching out of viewer navigation. [Home layout](../../addons/skin.estuary/xml/Home.xml) · [Home window](../../xbmc/windows/GUIWindowHome.cpp) · [Video details](../../xbmc/video/dialogs/GUIDialogVideoInfo.cpp) · [Video OSD](../../addons/skin.estuary/xml/VideoOSD.xml)
3. Use the local-information scanner and profile anchor convention already exercised by the fixture. For the first matched movie, find the existing anchor by qualified ID or create its anchor and NFO once under `special://profile/appliance/library/`. Configure the appliance movie/show roots through Kodi's video database APIs and queue the scan. Expose the resulting video library item to the UI. Retain any existing anchor at its original path. Repeated scans must reuse the same library ID. [Scanner](../../xbmc/video/VideoInfoScanner.cpp) · [Library queue](../../xbmc/video/VideoLibraryQueue.cpp) · [Video database](../../xbmc/video/VideoDatabase.h)
4. Follow `GetTitle → LoadIndexEntry → LocalFiles` and `CApplication::PlayFile → TryApplianceSource`. Persist the matched copy before making its anchor playable. Use per-title lookups for the generated index. Today's `LoadIndexEntry` reparses all of `index.json` on Play and rejects files above 2 MiB. A minimal option is one atomically replaced row per validated title key, with the legacy index as a read fallback. Serialize scan and catalog updates to the same row so an artwork refresh cannot erase local copies. Reconcile interrupted anchor/index writes idempotently on the next scan. Keep favorites in Kodi's favorites service and library IDs and title bookmarks in the Kodi video database. [Index and title recognition](../../xbmc/video/AppliancePlayback.cpp) · [Player entry and discovery scheduling](../../xbmc/application/Application.cpp) · [Favorites service](../../xbmc/favourites/FavouritesService.cpp)

**Pass when** the fixture plays via Home, records a bookmark, restarts into Home and resumes the same movie. Count zero release-discovery and resolver requests on a local hit. With local-only selected and the file unplugged, also count zero remote attempts after local exhaustion. Gate this in the playback scheduler, including Retry. Opening an ordinary video file must still reach standard Kodi playback.

## 2. Settle the two external dependencies early

Start discovery evaluation and TMDB registration alongside step 1. Record the provider comparison and registration outcome in the handoff. The first offline playback check needs neither service.

| Decision | Evidence needed to proceed |

Evaluate which providers the appliance can reach directly and choose the smallest set that meets the coverage target. Record operator, documented API and identifier mapping, rights to distribute/use it in this product, credential requirements, limits and failure behavior. A Stremio-compatible stream response with a hash and optional file index is one candidate format. Confirm the service itself permits the intended use. The default must work with Prowlarr unconfigured and the owner’s home server offline. Keep each friend's TorBox credentials on their Pi. [Stream response](https://github.com/Stremio/stremio-addon-sdk/blob/master/docs/api/responses/stream.md) |
| Coverage | Run the same representative movie, standalone episode and season-pack/conflicting-numbering cases against the candidate set and the owner’s normal Fen Light+ and CoCoScrapers setup with Prowlarr enabled. Run the appliance side with Prowlarr unconfigured and the owner’s home server unavailable. Record per case whether each found a release, confirmed the correct member, found it cached and started playback. Include an uncached and an ambiguous negative control. Keep source captures private. Publish counts, failure reasons and the selection rationale. Require coverage close to the owner's Fen Light+ setup. Choose a representative private sample before testing. Compare both setups close together using the same TorBox account. Report the fraction of Fen-playable movies the appliance also plays, and the equivalent fraction for episodes. Review the misses with the owner before selecting a default. If coverage or usage terms rule out a candidate, record the gap and evaluate another provider the appliance can reach directly. |
| TMDB catalog access | The owner chose a project application read token bundled in the non-commercial image for trusted friends. Register that use, confirm the applicable credential terms, and include the approved logo and notice in About or Credits. Inject the token from outside Git during private packaging. Treat it as extractable and support replacement in a subsequent build. Verify search on a fresh image without viewer registration. ## 3. Finish first boot, network and account settings

1. Give the appliance one first-run owner. Trace Kodi startup through first-window selection and Home initialization. On the pinned OS, LibreELEC's settings service independently starts its wizard when `libreelec/wizard_completed` is absent. Use a small derivative overlay to hand off first run and expose the existing ConnMan network selection if needed. Keep the service running for network and update duties. The pinned add-on's default entry opens its full settings window. Verify the network-only entry on the image. [Kodi startup](../../xbmc/windows/GUIWindowStartup.cpp) · [Pinned settings recipe](https://github.com/LibreELEC/LibreELEC.tv/blob/6209f5a3b067c45fbf527286dd84ee483294b46a/packages/mediacenter/LibreELEC-settings/package.mk) · [Service startup](https://github.com/LibreELEC/service.libreelec.settings/blob/6ff1cf26381d7a29c95886cdd0b7b222978ebb1d/service.py) · [ConnMan UI](https://github.com/LibreELEC/service.libreelec.settings/blob/6ff1cf26381d7a29c95886cdd0b7b222978ebb1d/resources/lib/modules/connman.py)
2. Detect connected Ethernet. Otherwise offer Wi-Fi scan, SSID selection and masked passphrase entry with the TV keyboard. Handle a bad password, lost connection, Retry, Back and offline setup. Then offer **Link TorBox**, **Enter key** and **Use local media**. Provide optional iOS setup or Skip before Home. Persist completion only after the chosen path succeeds. After interruption, reuse valid network/account state and return to the unfinished step. Network and account settings must remain reachable from Home.
3. Implement the device flow against the TorBox contract. Start with `GET /v1/api/user/auth/device/start`, show the code, readable verification link and a QR for the verification link, then poll `POST /v1/api/user/auth/device/token` at the returned interval. Handle pending, expired, already collected, rate-limited, offline and canceled responses. Invalidate old polls on Back, restart or profile change. Validate either returned or manually entered credentials through `/v1/api/user/me` before replacing the saved account. Unlink cancels outstanding work and returns to local-only playback. [TorBox API schema](https://api.torbox.app/openapi.json)
4. Reuse the profile provider configuration and secret-safe transport. The existing `GetJson` supports GET and discards HTTP error bodies. Add the bounded POST and status handling needed to distinguish polling outcomes. Keep keys, device codes, signed URLs and request bodies out of logs, skin properties exposed to remotes, and fixtures committed to Git. Save account changes atomically with owner-only permissions on the Pi. Account replacement must preserve optional Prowlarr settings. [Existing transport and provider loader](../../xbmc/video/AppliancePlayback.cpp)

**Pass when** loopback tests cover success, pending then expiry, a late success after Back, invalid manual entry, relink and unlink. Restart each completed mode. Verify that skipping setup extras reaches Home and a failed credential replacement preserves a working account. On the image, test Ethernet and Wi-Fi from fresh setup separately and verify there is exactly one wizard.

## 4. Complete catalog search, folder indexing and settings

- **Search and browse.** Return cached library matches immediately. In online mode, request TMDB movie/show results, seasons, episodes, details and artwork on background jobs. Bind replies to the current query and profile. A late reply after Back or a new query must leave the current list alone. Merge by media type and provider-qualified ID. Use the episode ID for playback and the series ID for shared language choice. Pass runtime in known units, original language and supported content hints to M3. Persist selected details and reuse the same anchor when a title is favorited, played or matched locally. Search, Favorites, Continue Watching and iOS must open that same library record. Check offline artwork fallbacks and the path from a show to a specific episode. [Video library API](../../xbmc/interfaces/json-rpc/VideoLibrary.cpp) · [Existing title and language fields](../../xbmc/video/AppliancePlayback.h)
- **Media folders.** Support optional USB/local directories and read-only SMB sources through the existing file browser, source settings, VFS and password manager. Store credential-free canonical paths in the index. Scan off the GUI thread, prioritizing NFO/explicit IDs, then unambiguous filename matches. Group multiple copies under one title. Keep ambiguous and unmatched files accessible with a manual match/correction action. Keep the last successful index on partial scans, access failure or a sleeping NAS. Removing a configured source detaches its copies while retaining titles, favorites and progress. [Folder browser](../../xbmc/dialogs/GUIDialogFileBrowser.cpp) · [Source settings](../../xbmc/settings/MediaSourceSettings.cpp) · [SMB credential handling](../../xbmc/PasswordManager.cpp) · [NFO reader](../../xbmc/NfoFile.cpp)
- **Viewer settings.** Surface Network, TorBox, Media folders, optional iOS pairing, audio/subtitle languages, M3's quality profile and separate movie/TV/anime language choices. Put optional Prowlarr URL/key, data caps and device overrides under Advanced. Wire these into the playback attempt. Today it sets the quality profile and language requirements while `RankFiles` already accepts device limits and preferences. Read Kodi's current display/player capabilities where established, retain unknowns where inconclusive, and refresh after changing HDMI chains. [Existing setting definitions](../../system/settings/settings.xml) · [Attempt construction](../../xbmc/application/Application.cpp)

**Pass when** the fixture covers two copies of one movie, two episodes of one show, an ambiguous file corrected by the viewer, a disconnected share and a restart. Assert one card per matched title, separate episode bookmarks, and the same saved language for that series. Add a local copy after remote playback and resume it from Favorites with zero resolver calls. Change one data cap and verify it filters a remote candidate while leaving an eligible local copy playable.

## 5. Connect the chosen release adapter to TorBox

1. Replace the Prowlarr prerequisite in `Discover`. Accept releases from the built-in adapter and from Prowlarr only when configured. Normalize each provider's title/episode identifiers, hash, member hints, reported size and provenance into the existing candidate model. Keep one source's valid results when another times out. Use bounded requests, response sizes and the existing attempt cancellation/deadline. Start release discovery only after eligible local copies are exhausted. Catalog search and release discovery are separate requests. [Current discovery, member selection and resolution](../../xbmc/video/AppliancePlayback.cpp)
2. Close the pilot's empty-account gap. Today it intersects search results with the first 200 ready torrents in TorBox `mylist`. Use cache availability and member evidence to build the eligible set. Reuse an existing ready account item when available. If a selected cached release needs acquisition, request it on demand with `add_only_if_cached`. Recheck/reuse the resulting torrent on duplicate Play or a lost response. Handle a cache miss or eviction without queuing an uncached job. Verify how the chosen provider's member index maps to TorBox's actual path and file ID. Where evidence is insufficient to identify an exact episode, advance to another eligible candidate. [TorBox torrent API](https://api-docs.torbox.app/)
3. Feed M3 the stable hash/member identity and exact member bytes when available. Label pack totals and unknown sizes explicitly. Merge duplicate reports, preserve distinct resolver routes, and resolve a fresh link only for the selected route. Keep Stop, EOF, cancellation, stale-callback handling, retry budgets, manual selection and quick replay on the M3 path. [Playback contract](stream-selection.md#playback-retry-and-resume)

**Pass when** a loopback account starting with an empty list plays a cached movie and the correct packed episode with Prowlarr absent. Count cache-only additions and per-file resolutions. Repeat with both discovery sources reporting the same member, a failed optional adapter, an expired link, an ambiguous pack and an evicted cache entry. An uncached-only result ends with a clear reason and zero uncached jobs. Repeat the successful cases live using the chosen default on the fresh household network.

## 6. Pair the official iOS remote

Offer pairing in setup and Settings. Start from Kodi's existing HTTP JSON-RPC authentication and Zeroconf service publication. Establish credentials unique to the installation before enabling LAN control, show the connection details on the TV for entry in Official Kodi Remote, and allow disabling or rotating access. Check which transports the app actually uses for discovery, text input, Now Playing and controls. Kodi's raw TCP JSON-RPC bind is controlled separately by `services.esallinterfaces`. Check from a second LAN client that every exposed control path requires authorization. If a required iOS feature uses an unauthenticated listener, document and resolve that transport gap before accepting pairing. [Network services](../../xbmc/network/NetworkServices.cpp) · [Player.Open](../../xbmc/interfaces/json-rpc/PlayerOperations.cpp)

**Pass when** skipped pairing leaves LAN control closed, missing/incorrect credentials cannot control playback, and the paired app rediscovers the Pi after restart. On the phone, enter search text, open the same movie and episode by library ID, inspect Now Playing, pause, seek, stop and resume. Compare title, selected file and bookmark with the TV route. Revoke access and verify the old credentials fail.
